*PADRÃO DE SEGURANÇA:*
- login obrigatório para áreas internas;
- Supabase Auth quando utilizado;
- RLS em tabelas sensíveis;
- policies por usuário/organização/perfil;
- signup/anon bloqueados quando desnecessários;
- nunca service_role no frontend;
- anon key + RLS no frontend;
- secrets em Environment Variables;
- autorização validada no backend/banco;
- usuário inativo sem acesso;
- sessão/logout/expiração tratados;
- validação/sanitização de inputs;
- NOT NULL/CHECK/UNIQUE/FKs;
- transações em operações críticas;
- dependências verificadas antes de excluir;
- sem DELETE CASCADE indiscriminado;
- erros sem vazar detalhes internos;
- logs/auditoria;
- tokens fortes, hash no banco, expiração e revogação;
- RPC pública mínima;
- SECURITY DEFINER somente quando necessário e validado;
- backup/exportação;
- HTTPS;
- produção separada de preview/desenvolvimento;
- proteção contra duplicidade/idempotência;
- minimização de dados pessoais;
- MFA/TOTP para administradores;
- rate limit;
- CAPTCHA público quando aplicável;
- auditoria de RLS;
- testes de acesso direto pela API.


REGRAS DE QUALIDADE:
- não inventar dados, avaliações, métricas, clientes, preços ou provas;
- não copiar referências; extrair princípios;
- verificar licenças de assets/código/fontes/componentes;
- não sacrificar funcionamento por efeito visual;
- executar loop IMPLEMENTAR → RENDERIZAR/TESTAR → CRITICAR → CORRIGIR;
- antes de produção, executar quality gate funcional, visual, mobile, acessibilidade, performance e segurança;
- antes de deploy, build local deve estar limpo.
